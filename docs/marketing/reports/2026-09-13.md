## New tech worth adopting

**Hybrid AI routing** is the concrete 2026 pattern, not just "costs are falling": send high-volume, easy requests (structured extraction, classification, form-field parsing) to a cheap open-weight model ($0.04–$0.15/million input tokens), reserve a stronger model for the genuinely hard requests (actual hazard-analysis generation). Quality loss on the easy bucket is reportedly small (~2%) even with big cost drops (~56%). *Effort: a routing change, not a rebuild.*

### Correction, added 2026-09-14 after auditing the code

**This recommendation does not apply to FORA, and the standing "audit AI calls" item is closed rather than carried a sixth week.** An audit of every AI call site in the repo found all three already running on the cheap model:

| Call site | Model | Workload |
|---|---|---|
| `api/generate-flha.js:128` | `claude-haiku-4-5` | FLHA hazard analysis, `max_tokens: 6000` |
| `server-lib/onboardingDrafting.js:29` | `claude-haiku-4-5` | SOP parsing, equipment-list extraction |
| `server-lib/companyBrainSummary.js:28` | `claude-haiku-4-5` | Company Brain signal summarization |

There is no easy/hard split left to make, because there is no expensive bucket to move off. The cost saving this item has promised for five weeks running is already banked.

**What the audit did surface is the opposite problem.** FORA's single hardest and most customer-visible AI call, the actual FLHA hazard analysis, runs on the cheapest model available. The two genuinely "easy bucket" workloads by the report's own definition (structured extraction in `onboardingDrafting`, summarization in `companyBrainSummary`) are correctly placed; hazard generation arguably is not. That is a **quality** decision with a cost attached, not a cost saving, so it is not something this pipeline should decide on the strength of a market-trend article. Flagged for a deliberate call, with instrumenting real per-document cost as the cheap first step if one is wanted.

**Research lesson for future weeks:** this item recurred five weeks running as "still open / unactioned" without anyone checking whether it applied. A finding that recommends a change to FORA's own stack should be checked against FORA's own code before it rolls over a second time.

# FORA Weekly Competitive Intelligence — 2026-08-16

## TL;DR

Two things worth your attention this week. First, Mitti (SafetyCulture) shipped exactly the "forms → patterns" AI feature the baseline analysis flagged as FORA's opening — worth a narrow, cheap answer rather than a scramble. Second, a solo-founder startup called Gewerkton just entered beta with a voice-first "worker explains the job, AI generates the record" platform — currently EU-standards-first, so not an immediate collision, but it validates FORA's exact wedge and is worth tracking as it expands. On the cost side: open-weight LLM inference is now 50–90% cheaper than frontier APIs, and on-device Whisper transcription is mainstream-viable — together these point at a real opportunity to make FORA's voice input both offline-capable and cheaper to run in one move.

They're also messaging hard on AI-data-privacy (contractual bans on training on customer data), which is worth noting as a trust point buyers may start expecting from everyone. - **GoCanvas** ($29–59/user/mo) and **MaintainX** ($65/user/mo Premium) both confirmed as meaningfully more expensive per-seat than FORA's flat tiers at any real headcount. ([source](https://www.capterra.com/p/139882/Canvas-Mobile-Forms/), [source](https://toolradar.com/tools/maintainx))

## Pain points discovered

- **Per-seat pricing is an explicit, financially-quantified budget complaint** for small/mid contractors in 2026 buyer coverage — described as making "the CFO wince," and pushing companies to ration software access to control cost, which defeats the point. Typical range: $49–149/seat/month. This sharpens baseline pain point #16 (enterprise tools overbuilt for small/mid contractors) — it's not just feature bloat, per-seat billing itself is the budget breaker. (#16, sharpened) ([source](https://dancumberlandlabs.com/blog/cheapest-construction-management-software/))
- Dashpivot reviews: hard for blue-collar workers to use when rollout/setup isn't done carefully; analytics depth trails dedicated BI tools. (new) ([source](https://ehsreviews.com/dashpivot-review/))
- HammerTech: no bulk worker import, no cross-project SDS transfer. (#6 — duplicate/repetitive data entry) ([source](https://www.capterra.com/p/186670/HammerTech/reviews/))

## Mid-market opportunity notes

This week's research sharpens rather than changes the existing bet in `docs/competitive-notes.md`: flat-tier pricing isn't just a nice-to-have, it's addressing a named, quantified budget pain point buyers are actively complaining about in 2026. Worth putting an actual number on the pricing page (e.g. "a 30-person crew on a $49–149/seat tool pays $1,470–$4,470/month — FORA's flat Advanced tier is a fraction of that") rather than only stating "no per-seat fees." Separately, small-contractor buying guidance this week explicitly told buyers to pick single-purpose best-of-breed tools rather than one do-everything platform — reinforcing that FORA doesn't need Mitti/HammerTech's breadth to win here, just to be the clear best answer for field documentation specifically.

## New tech worth adopting

- **Open-weight LLM inference at 50–90% lower cost than frontier APIs** (Groq, Together AI, Fireworks AI, inference.net serving Llama 4/Mistral/DeepSeek/Qwen-class models). *Effort: likely config/routing work, not a rebuild* — worth auditing which of FORA's AI calls (structured extraction, classification, non-frontier-reasoning generation) could route to an open-weight provider without a quality hit.
- **On-device Whisper-class transcription is now mainstream-viable** on-phone (NPU-accelerated), not a niche privacy feature. *Effort: a real feature project, but a well-scoped one* — this could make voice input work fully offline and eliminate per-request STT API cost at the same time.
- **Vision-model photo review on existing uploads** (the lightweight version of what Voxel AI/Mitti do with dedicated cameras). *Effort: moderate — a new pass on an existing pipeline*, no new hardware or camera infra needed since FORA already has a signed-photo-upload flow.

## Out-of-the-box recommendation

Don't treat "offline capability" and "voice API cost" as two separate backlog items — they converge on the same fix. Route voice capture through on-device transcription first (queue the transcript for AI processing when back online); it directly closes the offline gap flagged in `docs/scope-offline-capability.md` *and* removes a recurring per-request cost line, in one build instead of two.
